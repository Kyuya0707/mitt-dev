# KnowValue 正式仕様書・実装差分

- 文書版: 1.0
- 確定日: 2026-08-16
- コード判定基準: `main` ブランチ（2026-08-16 時点）
- 対象サービス: KnowValue

## 1. この文書の位置付け

この文書は、KnowValue の確定したプロダクト要件と、現行コードとの差分を一つにまとめた正式仕様書である。

- 本文の「正式要件」を今後の実装・テスト・運用判断の基準とする。
- `AGENTS.md`、`docs/CURRENT_STATE.md`、利用規約・法的表示、画面文言と内容が食い違う場合は、この文書を優先して修正する。
- ステータス判定はコード監査時点のスナップショットであり、実装後に更新する。
- Stripe の取扱可否、本人確認、特定商取引法・資金決済法・税務等は、Stripe の書面承認と専門家確認を得たうえで本番運用する。

### 判定の定義

| 判定 | 意味 |
| --- | --- |
| 実装済み | 確定要件を現行コードが満たしている。軽微な表示調整は含めない |
| 修正必要 | 関連機能はあるが、確定要件と挙動・金額・公開範囲・安全性が異なる |
| 未実装 | 要件を満たす処理、画面、データ構造、運用機能が存在しない |

## 2. プロダクト方針

### 2.1 コンセプト

> あなたの経験は、AIよりも価値がある。

KnowValue は「信頼が通貨になる市場」であり、実体験と人間の知識へ正当に報酬を支払う、有料Q&Aマーケットである。

- 広告を掲載しない。
- 実体験・専門経験・生活知を重視する。
- 信頼度と実績を可視化する。
- AIが生成・要約・翻訳・校正・編集した投稿は禁止する。
- AI違反は自己申告、通報、運営確認により判断し、AI検出器だけで自動処分しない。
- 初回の違反確認では対象投稿を削除し、再違反では利用停止を行う。

### 2.2 利用対象

- 18歳以上であれば、職業や経験年数を問わず利用できる。
- 質問・回答の初回投稿前に本人確認を完了する。
- 閲覧のみの場合はアカウント登録を必須としない。

### 2.3 カテゴリ

採用するカテゴリは次の10種類とする。

1. 育児・子育て
2. 転職・キャリア
3. プログラミング・IT
4. 仕事術・職場の悩み
5. 学習・資格
6. 恋愛・人間関係
7. 暮らし・家事
8. 旅行・地域情報
9. 趣味・創作
10. 商品選び・購入体験

次の分野は取り扱わない。

- 投資、暗号資産、個別銘柄の推奨などの金融分野
- 医療診断・治療判断
- 法律判断・個別の法的助言
- ギャンブル、占い
- 転売利益を目的とする手法

## 3. アカウント、本人確認、プライバシー

- 公開名はニックネームのみとし、本名を一切公開しない。
- 本名、メールアドレス、本人確認資料、口座・決済情報は公開しない。
- 本人確認資料、セルフィー、銀行口座番号をKnowValue DBへ保存しない。StripeのアカウントIDと確認ステータスだけを保持する。
- 回答報酬を受け取るユーザーは、KnowValueの設定画面からStripe Connectのオンボーディングを開始する。
- 本人確認・口座登録時のみStripeのホスト画面へ一時遷移し、完了後はKnowValueへ戻る。
- 利用者にStripe独自の設定や事業内容・MCCの入力をさせない。事業情報はプラットフォーム側で管理する。
- 通常利用でStripeダッシュボードを操作させない。ただしStripeから追加確認が必要な場合は、KnowValue設定画面から対応画面へ案内する。
- ユーザーは自分のアカウントで任意に2要素認証を有効化でき、運営アカウントは2要素認証を必須とする。

## 4. 質問、報酬、決済

### 4.1 質問投稿

- 質問報酬の最低額は500円とする。
- 投稿時に、質問者は「質問報酬 + 質問報酬の10%のプラットフォーム利用料」を支払う。
- 質問のタイトル、本文、カテゴリ、報酬額は公開後に変更できない。
- 補足は追記としてのみ追加でき、元本文は残す。追記日時を表示し、回答済みユーザー全員へアプリ内通知し、メールは各ユーザー設定に従う。
- 質問には公開後の回答期限を設定する。通常の最短期限は14日後とする。
- 回答期限を過ぎても、BEST決定またはキャンセル承認までは回答を受け付ける。
- 期限延長は期限前だけ可能とし、期限後の変更と通常操作による短縮は禁止する。

### 4.2 BEST回答と報酬

- 質問者は一つの回答だけをBEST回答に選ぶ。
- BEST選択前に確認画面を表示し、選択後はユーザー操作で取り消せない。例外対応は運営だけが行う。
- BEST回答者へ質問報酬の90%を付与し、質問報酬の10%をプラットフォーム収益とする。
- 質問投稿時に質問者が別途支払った10%の利用料もプラットフォーム収益とする。
- 回答報酬はまずサービス内残高へ記帳する。
- 毎月の締め処理で残高が5,000円以上なら全額をまとめて振り込み、5,000円未満は翌月へ繰り越す。
- 振込手数料はプラットフォームが負担する。
- 明細には日付、種別、総額、手数料、純額、処理状態を表示し、月次・年次CSVを出力できるようにする。

### 4.3 BEST未選択の制御

- 回答期限を過ぎてBEST未選択の質問がある場合、質問者は新しい質問を投稿できない。
- BEST選択のアプリ内通知は必須とし、メールは初期値ONで設定画面から停止できる。
- 通知日は「回答期限当日、3日後、7日後、その後30日ごと」とする。
- 良い回答が来ない場合は、回答待ち、再報酬設定、またはキャンセル審査を利用できる。

### 4.4 90日ルール

- 報酬が有効な質問期間は、決済完了から最大90日とする。
- 75日目、85日目、89日目に終了予告を通知する。アプリ内通知は必須、メールは設定に従う。
- 90日経過時点でBEST未選択なら、質問報酬を質問者へ自動返金する。
- 質問と既存回答は削除せず、質問を「報酬停止中」にし、新しい回答を停止する。
- 質問者は同じ質問へ「新しい質問報酬 + 10%利用料」を支払うことで、新たな90日間を開始できる。
- 以前の10%利用料とBoost料金は返金しない。
- 報酬停止中も、新規質問の投稿制限は継続する。解除には再報酬設定後のBEST選択、またはキャンセル承認が必要となる。
- 回答者間への自動分配は行わない。

### 4.5 キャンセル

- 質問者は回答期限経過後にキャンセルを申請できる。
- 回答が一件もない場合は自動承認する。
- 回答がある場合は運営が内容を確認する。
- 未回答同然、規約違反、明らかな低品質のみなら承認し、妥当な回答がある場合は却下してBEST選択または回答待ちを案内する。
- 承認後は質問を非公開にする。匿名公開やURL直接閲覧も認めない。
- 承認時は質問報酬を全額返金するが、10%利用料とBoost料金は返金しない。
- プラットフォーム障害など運営責任の場合だけ、利用料を含む全額返金を可能とする。

## 5. Boost

- 質問報酬が3,000円以上の場合だけ利用できる。
- 1回の料金は質問報酬の10%とする。
- 一つの質問につき最大3回まで利用できる。
- 1回につき3日間、質問一覧の上部へ移動し、強調表示する。
- Boostにより回答期限を最短7日まで短縮できる。7日未満にはできない。
- 再Boost時は再度上部へ移動する。

## 6. 回答、コメント、公開範囲

### 6.1 回答

- 一人のユーザーが一つの質問へ投稿できる回答は一件だけとする。
- BEST選択前は、各回答を質問者とその回答者だけが閲覧できる。
- BEST選択後も、非BEST回答は質問者とその回答者だけが閲覧できる。
- 回答者はBEST選択前に限り、自分の回答を編集・削除できる。
- BEST選択後の変更は運営対応に限る。
- 回答画像は最大3枚、1枚5MBまで、JPEG・PNG・WebPのみとし、位置情報等のメタデータを削除する。
- 回答の閲覧権限は画像にも同じように適用し、非公開画像を公開URLで配信しない。

### 6.2 コメントと「参考になった」

- コメントは回答ごとに設け、質問者とその回答者だけが閲覧・投稿できる。
- ダイレクトメッセージ機能は設けない。
- 「参考になった」は質問者がすべての回答へ付けられる。
- 有料BESTの購入者も購入したBESTへ付けられる。
- 一人につき一回答へ一回までとし、自分の回答への評価は禁止する。

## 7. 有料BEST回答

- BEST回答の本文は有料コンテンツとしてロックする。
- 質問者とBEST回答者は無料で全文を閲覧できる。
- その他のユーザーは、質問者が設定した100円から100,000円の閲覧価格を支払って閲覧する。
- 質問者は後から閲覧価格を変更できるが、既購入者の権利は失われない。
- 未購入者へ意味のある本文プレビューを表示しない。
- 購入後はその購入者が恒久的に閲覧できる。
- 売上は「質問者50%、BEST回答者20%、プラットフォーム30%」で分配する。
- 購入後の自己都合返金は行わない。規約違反による削除やプラットフォーム障害で閲覧不能となった場合は全額返金する。
- 購入にはアカウント登録とログインを必要とする。

## 8. 報酬交渉

- 回答者は質問者へ追加報酬を提案できる。他のユーザーの回答は妨げない。
- 承認時に質問者は「追加報酬 + 追加報酬の10%利用料」を支払う。
- 交渉成立者が7日以内に回答を投稿した時点で、追加報酬の90%をその回答者へ付与する。
- 7日以内に投稿されなければ追加報酬を全額返金する。
- 追加報酬は、その回答がBESTに選ばれなくても返金しない。
- 元の質問報酬はBEST回答者だけへ支払う。

## 9. 質問の公開、検索、一覧

- 未ログインユーザーも、支払い済みの公開質問について、タイトル、本文、画像、報酬額、期限、回答数を閲覧できる。
- 未ログインユーザーは回答、コメント、購入を行えない。
- 公開質問は検索エンジンのインデックス対象とする。
- 未払い、キャンセル承認済み、非公開の質問は一覧・直接URLとも閲覧不可とし、`noindex` とする。
- 回答本文は回答数以外を質問一覧へ表示しない。
- 一覧の絞り込みはカテゴリ、キーワード、報酬額、期限とする。
- 並び順は新着、報酬額、期限、回答数を提供し、Boost中の質問を優先表示する。

## 10. 信頼スコア、プロフィール、ランキング

### 10.1 公開プロフィール

公開する情報は次の項目に限定する。

- ニックネーム、自己紹介
- 経験カテゴリ、経験年数
- 本人確認済みバッジ
- BEST回答数、「参考になった」数
- 信頼スコア、ランク

外部連絡先、SNS、投資成績、資産額は掲載させない。

### 10.2 信頼スコア

- 0から100で表示し、日次で更新する。
- ランクは Bronze、Silver、Gold、Platinum、Black の5段階とする。
- BEST獲得、「参考になった」、規約を守った継続利用を加点要素とする。
- 通報件数だけでは減点しない。運営が確認した規約違反、AI利用、スパム、削除を減点要素とする。
- 投資歴、資産額、利益等の自己申告値をスコアに使わない。

### 10.3 ランキングと興味カテゴリ

- `/ranking` に週間、月間、全期間ランキングを設ける。
- BEST回答数を主順位とし、ニックネーム、BEST回答数、信頼スコア、ランクを表示する。
- 興味カテゴリは一人3件まで登録できる。
- 興味カテゴリに新規質問が投稿された場合、アプリ内通知し、メールは設定に従う。

## 11. 通報、異議申立て、制裁

- 質問、回答、コメントを通報できる。
- 理由は「AI利用、禁止された金融助言、詐欺・虚偽、誹謗中傷・迷惑行為、著作権侵害、その他」とする。
- 通報だけでは非公開化・減点・利用停止を行わず、運営確認後に結果を反映する。
- 結果通知は通報を受けたユーザーだけへ送る。通報者の身元は相手へ開示せず、通報者への結果通知は行わない。
- 異議申立ては何度でも可能だが、新しい証拠または説明を必須とし、前回申立てから7日間の間隔を設ける。
- 通常の制裁は、警告、7日停止、30日停止、永久停止の順とする。
- 詐欺、なりすまし、重大な法令違反は直ちに永久停止できる。

## 12. 画像、リンク、著作権

- 質問画像も最大3枚、1枚5MB、JPEG・PNG・WebPのみとし、メタデータを削除する。
- 根拠資料などの一般公開リンクは許可する。
- アフィリエイト、紹介コード、LINE、Discord、個人SNS、外部連絡先への誘導は禁止する。
- 投稿の著作権は投稿者に残る。投稿者はKnowValueへ、表示・保存・販売に必要な範囲の利用許諾を与える。
- 有料BEST購入者の権利は閲覧に限り、無断転載・再配布・スクリーンショット共有を禁止する。

## 13. 通知、退会、運営

### 13.1 通知

- アプリ内通知は常時有効とする。
- 新しい回答、興味カテゴリの新しい質問、交渉提案等のメールはユーザーがON/OFFできる。
- パスワード・メールアドレス・受取口座の変更、返金、振込失敗、利用停止等のセキュリティ・金銭関連メールは停止不可とする。
- 振込予定、振込完了、振込失敗をアプリ内通知し、メールは確定した通知ルールに従う。失敗時はKnowValue設定画面からStripe確認へ誘導する。

### 13.2 退会

- 購入済みの有料BESTは、投稿者退会後も「退会済みユーザー」として匿名化し、購入者の閲覧権を維持する。
- 未販売の回答は引き続き質問者と回答者だけが閲覧できる。
- 未処理の振込、返金、通報がある間は退会処理を保留する。
- 法令・会計上必要な記録だけを最小限保持する。

### 13.3 運営機能

- 権限を Owner、Operations、Accounting に分離する。
- Owner は全権限、Operations は通報・キャンセル・ユーザー対応、Accounting は返金・振込・売上を担当する。
- 返金、振込、通報判断、利用停止、異議申立ての操作は監査ログへ残す。
- 問い合わせフォームを設け、決済・報酬、通報、アカウント等の区分と対応ステータスを管理する。

## 14. Stripe・インフラの確定方針

### 14.1 Stripe

- C to C の三者間取引をConnectなしで運用しない。
- Stripe Connectを利用して質問者、プラットフォーム、回答者間の資金移動を管理する。
- KnowValueの事業内容を偽装せず、実際のコンテンツマーケット事業としてStripeへ説明する。
- 本番運用前に、KnowValueのビジネスモデル、禁止カテゴリ、本人確認、返金・通報フローを提示し、Stripeから書面承認を得る。
- Stripeから取扱不可と判断された場合は、カテゴリ名だけを変更して回避せず、決済設計または事業設計を見直す。

### 14.2 Vercel・Supabaseリージョン確認結果

| 確認項目 | 現在確認できた内容 | 判定・対応 |
| --- | --- | --- |
| Vercel本番プロジェクト | `mitt-dev-lddm`（`knowvalue.jp`） | Vercel Dashboardで確認済み |
| Vercel入口PoP | 東京 `hnd1` | 確認済み |
| Vercel Functions実行リージョン | Singapore `sin1` | 2026-08-17にDashboardで変更し、本番レスポンスの `x-vercel-id: hnd1::sin1::...` で確認済み |
| リポジトリ内リージョン指定 | `vercel.json` なし | Vercelプロジェクト設定で`sin1`を明示指定 |
| Supabase本番プロジェクト | `mitproject`（project ref: `uzqvftqqdaqofvgnaxym`） | 本番クライアントの公開project refとDashboardを照合済み |
| Supabaseプロジェクトリージョン | Singapore `ap-southeast-1` | Supabase Dashboardで確認済み |
| Prisma実行時接続 | `DATABASE_URL` | `prisma/schema.prisma` で確認済み |
| Prisma migration直結 | `DIRECT_URL` | `prisma/schema.prisma` で確認済み |
| 本番 `DATABASE_URL` の接続方式 | Supavisor Transaction Pooler、ポート`6543`、`pgbouncer=true` | Vercelの秘密値を記録・公開せず、接続形式だけ確認済み |
| `connection_limit` | 未指定 | 障害ではない。実測負荷と同時接続数を見て必要なら追加する |
| Vercelの `DIRECT_URL` | 未登録 | 通常リクエストでは不要。migration実行環境にだけ安全に設定する |
| Vercelの `DATABASE_URL` 保護 | Sensitive、Production and Preview | 2026-08-17にSensitive変数として再登録し、値を再表示できない状態に変更済み |

パフォーマンス上の確定方針は次のとおりとする。

- Vercel FunctionsとSupabase DBは、原則として同一または最寄りリージョンへ配置する。
- Vercelのようなサーバーレス実行では、実行時接続にSupavisor Transaction Poolerを使用する。標準ポートは6543とし、Prisma向けに `pgbouncer=true` を設定する。
- `DIRECT_URL` はmigration等の管理処理に限定し、通常リクエストで直結を乱用しない。
- 現行のTransaction Pooler接続は維持し、リージョン最適化と同時に接続URLを変更しない。
- Supabaseプロジェクトのリージョン変更には新規プロジェクトへの移行が必要なため、バックアップ、Storage、Auth、環境変数、停止時間を含む移行計画を別途作成する。

2026-08-17の変更後に、本番の質問一覧へキャッシュ回避付きで3回アクセスした結果は次のとおりだった。

- 全リクエストが`200 OK`、実行リージョンは`sin1`。
- 初回確認のTTFBは約0.26〜1.96秒、続く5回の連続確認は約0.26〜0.54秒。継続的な評価にはSpeed Insights等の実ユーザー計測を別途有効化する。

## 16. 実装優先順位

### 優先度P0: 公開範囲・金銭事故の防止

1. 匿名APIのUser情報返却をallowlist化する。
2. 非BEST回答、コメント、回答画像を当事者以外へ一切返さない。
3. 取消承認済み・未払い質問を一覧と直接URLの両方で遮断する。
4. 有料BEST分配を50/20/30へ修正し、既存取引の扱いをmigration前に確定する。
5. キャンセル時の返金対象を質問報酬に限定する。

### 優先度P1: 主要プロダクトルール

1. 本人確認必須、18歳以上、期限14/7日、BEST未選択投稿ロックを実装する。
2. 90日ルール、再報酬、リマインドを実装する。
3. Boost、月次5,000円振込、明細CSVを実装する。
4. 一人一回答、回答編集削除、追記、「参考になった」権限制御を実装する。
5. 交渉決済を追加10%・投稿後90%・7日返金へ修正する。

### 優先度P2: 信頼・運用・法務

1. 通報、審査、異議申立て、制裁、監査ログ、管理ロールを実装する。
2. 信頼スコア、ランク、ランキング、プロフィール、興味カテゴリ上限を実装・修正する。
3. 画像制限・非公開配信、リンク制御、退会、問い合わせを実装する。
4. 規約、法的表示、返金方針、通知文言を本仕様へ統一する。
5. Stripe書面承認後に本番決済要件を最終固定する。

## 17. 変更時の安全ルール

- 既存本番フローを一度に大きく変更せず、小さな単位で実装・テスト・反映する。
- Prisma Schemaを変更する前に、migration影響、データ損失、本番リスクを説明する。
- 金額分配や公開範囲を変更するmigrationでは、既存レコードへ新ルールを遡及するかを明示する。
- 決済・返金・振込Webhookは冪等性を保証する。
- 公開APIは必要項目だけを明示選択し、Prismaの関連モデル全体を返さない。
- 本番反映前に、未ログイン、質問者、回答者、第三者購入者、運営の各権限でE2E確認する。
